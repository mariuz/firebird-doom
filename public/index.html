Co-op over the network — up to four players, peer to peer

Everyone loads the same WAD. The host presses Invite a player and sends the code to a friend (chat, e-mail…); the friend presses Join, pastes it and sends back the reply; the host pastes the reply and presses Connect. Invite up to three, then Start: the host's map and skill. Only each player's keys cross the wire, and every browser's Firebird plays the same game from them (lockstep, as DOOM did over IPX).

Click the view to capture the mouse · WASD / arrows move · Ctrl or click fire · Space/E use · Shift run · 1–7 weapons (1 again: chainsaw, 3 again: super shotgun) · Esc menu · Tab map (IDDT on it reveals all) · type IDDQD, IDKFA, IDFA, IDCLIP, IDCHOPPERS, IDBEHOLDx, IDMYPOS, IDMUSxy or IDCLEVxy to cheat · P pause (not in co-op) · M audio on/off. On touch screens the left half moves, the right half turns, and a tap fires.

How it works

      
    
        
  • The WAD becomes tables. VERTEXES, LINEDEFS, SIDEDEFS,
          SECTORS, SEGS, SSECTORS, NODES and THINGS
          are copied in as rows. Sprite frames and texture sizes become tables too.
    • 
        
  • The game is PSQL. DOOM_TIC runs at 35 Hz: player movement with wall sliding
          (CHECK_POSITION), doors and lifts (MOVERS), monster AI with line-of-sight
          (CHECK_SIGHT), hitscan weapons, rockets, plasma and the BFG (with splash damage and the 40-ray BFG spray), pickups,
          secrets, light effects, the boss-death specials, Commander Keen and the Icon of Sin.
    • 
        
  • The BSP is a recursive CTE. INIT_MAP finds every thing's sector by walking
          NODES for all things at once with WITH RECURSIVE.
    • 
        
  • The renderer is a query. FRAME_WALLS walks the BSP front to back like DOOM's
          R_RenderBSPNode. It skips subtrees whose bounding boxes are already hidden, and tracks
          solidsegs as one character per screen column. For each visible seg it intersects every column's
          ray, then carries DOOM's ceilingclip/floorclip window down each column. Switch
          Renderer to brute force to project every linedef instead (about 3× slower, same picture).
          FRAME_WALLS_WINDOWED states the clipping with MAX() OVER (PARTITION BY col ORDER BY depth).
          Each slice also reports the ceiling and floor rows it uncovers. The browser files those into visplanes and draws
          them as horizontal spans, like DOOM's R_MakeSpans; FRAME_VISPLANES lists them.
          FRAME_SPRITES picks the rotation frame for each monster.
    • 
        
  • Sound is a table too. Procedures insert rows into SOUND_EVENTS for gunfire, doors, lifts,
          switches, pickups, pain, deaths and monster sightings. The browser plays the WAD's DMX sound lumps,
          attenuated and panned from where the sound happened. Music is the WAD's MIDI/MUS lumps played by a small
          FM synthesiser that uses the WAD's own GENMIDI OPL2 instrument bank, as DOOM's Adlib driver did.
          Audio starts after your first click or key press.
    • 
        
  • JavaScript only paints. It looks up texels and colormaps for the rows Firebird returns.
    •
